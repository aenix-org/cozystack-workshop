## 14. Step 1: your own storage

**Creating a bucket for the image**

📍 **Where:** on the bastion, in the `~/workshop` directory.

The disk image weighs several gigabytes. It has to live somewhere so the cluster can later pull the file by a link. That is what object storage is for — the same idea as S3.

```bash
kubectl apply -f manifests/01-bucket.yaml
kubectl get buckets.apps.cozystack.io -n tenant-workshopXX
```

Wait until the bucket reaches a working state.

The manifest creates a bucket named **`my-images`** with a single user — `app`. In the dashboard it shows up under **Bucket**.

🖱 **Via the dashboard:** **Bucket → Deploy new**, name `my-images`. Just be sure to **add the user `app` to the `users` section right away**, before you create it. If you create an empty bucket and add the user later through Edit, the bucket stays half-finished and the image upload will fail. The manifest already takes care of this.

**Now grab the bucket's keys — you'll need them two steps from now.**

The bucket is locked, and to put anything into it you need its own access keys. They live in the dashboard: **Bucket → `my-images` → Secrets tab → the `bucket-my-images-app-credentials` secret**. Expand it and you'll see four values, each with a *Reveal* and a *Copy* button.

**What to do with them right now: copy three of them into a notepad** — anywhere at all, notes, a draft message to yourself:

• `bucketName`
• `accessKey`
• `secretKey`

⚠️ **`bucketName` is NOT `my-images`.** `my-images` is the name you gave to the order; the real name of the bucket in S3 was generated by the platform itself — long, of the form `bucket-a9209f83-4ac1-463e-8477-d8365bef787b`. That is exactly what goes into the script, from the `bucketName` field. Put in `my-images` and the upload will go to a bucket that doesn't exist and fail with `Insufficient permissions`. People have tripped over this at past workshops.

The fourth one, `endpoint`, you don't need to write down — it's the same for everyone and is already filled in in the script.

**Where they go.** In step 3 you'll open the file `convert.sh` on the converter machine, and in it a block "PASTE YOUR VALUES" of three lines:

```
BUCKET="ВСТАВЬТЕ_bucketName"
ACCESS_KEY="ВСТАВЬТЕ_accessKey"
SECRET_KEY="ВСТАВЬТЕ_secretKey"
```

Those are the exact three values you'll paste there, each inside its own quotes. They won't be needed anywhere else: the script itself will upload the finished image to your bucket and itself create a link to it.

⚠️ The secret key is the password to your storage. Don't post it in the shared chat, not even when you're asking for help. If something doesn't add up, message me privately.

⚠️ If you decide to change `endpoint` to your own: in the dashboard it's shown without a scheme (`s3.workshop.aenix.io`), but in the script it's written **with** `https://` at the start. Leave it off and the upload will silently fail.
