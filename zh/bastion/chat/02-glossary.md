## 2. 小词典：在你那边叫什么，在这里叫什么

**一条可以随时回看的消息**

工作坊上一半的困惑都不是技术本身造成的，而是词汇造成的。下面就是这份对照表。凡是类比会误导人的地方，我都会老实指出到底错在哪：错误的类比比没有类比更糟。

| 在 vSphere 里 | 在 Cozystack / Kubernetes 里 | 类比在哪里会误导人 |
|---|---|---|
| 虚拟机 | **VM Instance** | 这里没有任何误导，它就是虚拟机本身 |
| 虚拟机磁盘 | **VM Disk** | 一个独立的对象。没有磁盘就没有虚拟机，所以磁盘总是最先创建 |
| 虚拟机模板 | 目录中的镜像 | — |
| 应用容器 | **Pod** | Pod 是一次性的。它坏了不去修——而是删掉它，然后会创建一个新的 |
| vApp | **Deployment** | — |
| 资源池 | 带配额的**租户** | 租户同时也是一条访问边界：外人无法窥探其内部 |
| vCenter | API server | 控制台只是它的门面，而不是它本身 |
| HA | **Deployment** 保持 N 个副本 | 不是「把崩掉的那个拉起来」，而是「始终保持你所要求的那么多个」 |
| 负载均衡器池 | **Service** | — |
| Datastore | **Storage Class** | `replicated`——在三个节点上带复制，`local`——不带复制 |
| 单独一台装有 Postgres 的虚拟机 | **目录中的 Postgres** | 自带复制和备份，能自我更新 |
| 给 IT 部门提工单 | *无对应* | 你自己动手，一分钟就搞定 |

⚠️ **别把两台「虚拟机」搞混。** 在这条路径上，「虚拟机」这个词指的是 **bastion**——那台你通过 SSH 登录、并从上面指挥集群的共享机器。而你将在集群里启动的那台机器（先是转换器，然后是 app-VM），才是 **VM Instance**，我们把它叫作「你的机器」或「app-VM」。bastion 是你发号施令的地方；app-VM 是你在集群内部创建的东西。你在 bastion 上敲 `kubectl`/`virtctl` 命令，而 `netfix`、数据库结构和 `psql` 则都发生在 app-VM 内部（通过 `virtctl console`）。

**有一件事你得慢慢习惯。** 在 vSphere 里你**创建**一个对象：一点击——它就出现了，此后它自己独立存在。而在这里，你**描述期望状态**，集群则不断地把它与实际状态作比较，并消除两者之间的差异。所以如果你删掉某个东西，它可能会回来——不是因为出了故障，而是因为你从未撤销过那份「期望」。
