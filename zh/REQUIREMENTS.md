# 环境要求

面向为本次工作坊搭建环境的人，或想自行完成实验的人。参与者不需要这个文件。

## 租户配额

**每个租户至少 40 个 CPU 和 48 GB 内存。**

原因在于请求（request）配额的计算方式：它等于限制（limit）的十分之一。一个 `cpu: 16` 的租户只能得到 1600m 的请求配额——而实验 0 里的一个实验集群大约就要占用 1435m。这样一来，实验 6–12 中的托管服务就什么都不剩了，而实验 0 又明确要求你不要删除这个集群。

配额不够时的症状：事件里出现 `exceeded quota: tenant-quota`，集群永远卡在 `Unknown` 状态。它不会自己从这个状态里恢复出来。

## 创建租户

**一次一个，不要批量创建。**

同时创建多个并启用了存储和监控的租户，会把 helm-controller 的队列塞满：各个 release 陷入「安装—失败—删除」的循环，还带着十分钟的超时。诊断方法是看卡住的 HelmRelease 上的 `observedGeneration: -1`。

删除同理：一个内部带集群的租户要花好几分钟才能拆除，因为清理 job 会等待 worker 虚拟机被释放。

## 租户中必须启用什么

| 什么 | 为什么 | 实验 |
|---|---|---|
| etcd | 没有它，实验 0 的集群起不来 | 全部 |
| 存储（SeaweedFS） | Bucket 和 Harbor | 6、11 |
| 监控 | 指标和控制台（dashboard） | 3、14 |

如果租户启用了 etcd，`metrics-server` 会自动安装——不需要单独启用它。它位于 `cozy-monitoring` namespace 里，但并不属于监控插件的一部分。

## 平台版本

这些实验是在 **Cozystack v1.6.1** 上编写和验证的。在更早的版本上，部分目录（catalog）条目的名称不同，或者字段集合不同。
