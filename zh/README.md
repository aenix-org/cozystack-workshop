# 从 VMware 迁移到 Cozystack：工作坊与实验

面向 VMware 管理员的材料——如果你想弄清楚 Cozystack 到底是什么，不是靠看幻灯片，而是亲手上机。
你不需要懂 Kubernetes：一切都会在过程中讲清楚，借助你已经从 vSphere 熟知的东西来讲。

## 两种上手方式——挑选属于你的那种

同一套工作坊做成了两个版本。它们唯一的区别在于**你从哪里操作集群**。讲师会告诉你哪一个是你的。

| | [`laptop/`](laptop/) — 从你自己的笔记本 | [`bastion/`](bastion/) — 通过 bastion（跳板机） |
|---|---|---|
| **工具** | 你自己安装：`kubectl`、`virtctl`、`kubelogin` | 已经装在 bastion（跳板机）上 |
| **集群访问** | 从控制台（dashboard）拿 kubeconfig，通过浏览器登录 | 通过 SSH 登录，访问权限已经配好 |
| **文件里的租户编号** | 你自己填写 | 已经提前填好 |
| **检查应用** | `virtctl port-forward` + `localhost:8080` | 通过域名 `app.<number>.workshop.aenix.io` |
| **适合谁** | 没有共享 bastion（跳板机）的人 | 备好的、带 bastion 的测试环境 |

每个文件夹里都是一套自成一体的材料：各自的 `README.md`（路线）、`chat/`
（每一步对应的聊天消息）、`manifests/`、`scripts/`。打开你所选路径的 README，照着走。

## 实验

两个文件夹里都有 `labs/`——十六个独立的实验，你可以按自己的节奏完成，在家里或者休息时间里做。
每个实验都带自己的检查脚本（`check/`）。整套大约九个小时，不适合一次做完：一晚上做一个。

| 实验 | 内容 | 时间 |
|---|---|---|
| 0 · 你自己的集群 | 十分钟给自己弄一个 Kubernetes | 15 分钟 |
| 1 · 第一个应用 | 用一个文件、一条命令部署一个应用 | 25 分钟 |
| 2 · 自愈 | 删掉一个副本，看看会发生什么 | 25 分钟 |
| 3 · 扩缩容 | 施加负载，观察副本增长 | 30 分钟 |
| 4 · 滚动发布与回滚 | 在负载下切换版本，且零停机 | 30 分钟 |
| 5 · 用 Git 管理基础设施 | 把一切都写进仓库，用一次 push 发布出去 | 40 分钟 |
| 6 · 你自己的镜像仓库 | Harbor，构建一个 Go 服务，从自己的镜像仓库部署 | 45 分钟 |
| 7 · 缓存 | 在慢后端前面放 Redis，用数字看收益 | 50 分钟 |
| 8 · 密钥 | 把密码从清单里挪到 OpenBao | 50 分钟 |
| 9 · 分析 | 一百万行数据，报表在毫秒内出来 | 45 分钟 |
| 10 · 文档型数据 | 当记录形状各不相同时，用 MongoDB | 45 分钟 |
| 11 · 移动端构建 | 在集群里构建一个 APK，扔进一个 bucket | 40 分钟 |
| 12 · 顺带一台虚拟机 | 遗留系统不必容器化也能搬过来 | 30 分钟 |
| 13 · 把自己的东西放进目录 | 把一个应用打包成 Cozystack 应用 | 40 分钟 |
| 14 · 可观测性 | 在图表里找到你自己那份负载留下的踪迹 | 30 分钟 |
| 15 · 周一该做什么 | 从哪个系统开始，以及向管理层承诺什么 | 20 分钟 |

各实验的链接在你所选路径的 README 里：[`laptop/labs/`](laptop/labs/) 或
[`bastion/labs/`](bastion/labs/)。
