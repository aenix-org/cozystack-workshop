# VMware から Cozystack への移行：ワークショップとラボ

VMware を管理していて、Cozystack とは何なのかをスライドではなく実際に手を動かして
理解したい方のための教材です。Kubernetes の知識は必要ありません。すべては進めながら、
あなたがすでに vSphere で知っていることを通して説明します。

## 受講方法は2つ — 自分に合うものを選ぶ

同じワークショップが2つのバリエーションで用意されています。違いは**どこからクラスターを
操作するか**だけです。どちらがあなたのものかは講師が伝えます。

| | [`laptop/`](laptop/) — 自分のノートPCから | [`bastion/`](bastion/) — bastion 経由 |
|---|---|---|
| **ツール** | 自分でインストールします：`kubectl`、`virtctl`、`kubelogin` | bastion にインストール済み |
| **クラスターへのアクセス** | ダッシュボードから取得した kubeconfig、ブラウザ経由でサインイン | SSH でログイン、アクセスは設定済み |
| **ファイル内のテナント番号** | 自分で記入します | あらかじめ記入済み |
| **アプリの確認** | `virtctl port-forward` + `localhost:8080` | ドメイン名 `app.<番号>.workshop.aenix.io` で |
| **対象者** | 共有の bastion がない方 | bastion 付きの用意されたテスト環境がある方 |

各フォルダの中には、それだけで完結するセットが入っています。それぞれの `README.md`
（進め方）、`chat/`（各ステップのチャット用メッセージ）、`manifests/`、`scripts/` です。
自分の経路の README を開いて、それに沿って進めてください。

## ラボ

どちらのフォルダにも `labs/` が入っています。16個の独立したラボで、自分のペースで、
自宅や休憩時間に進めます。それぞれに独自のチェックスクリプト（`check/`）が付いています。
全体で約9時間、一度に終わらせるものではありません。1晩に1つずつ取り組んでください。

| ラボ | 内容 | 所要時間 |
|---|---|---|
| 0 · 自分のクラスター | 10分で自分の Kubernetes を用意する | 15分 |
| 1 · 最初のアプリケーション | 1つのファイルと1つのコマンドでアプリケーションをデプロイする | 25分 |
| 2 · 自己修復 | レプリカを削除して何が起きるか見る | 25分 |
| 3 · スケーリング | 負荷をかけてレプリカが増えるのを見る | 30分 |
| 4 · ロールアウトとロールバック | 負荷をかけたままバージョンを変更する、ダウンタイムなしで | 30分 |
| 5 · Git 上のインフラ | すべてをリポジトリに記述し push で出荷する | 40分 |
| 6 · 自分のレジストリ | Harbor、Go サービスのビルド、自分のレジストリからのデプロイ | 45分 |
| 7 · キャッシュ | 遅いバックエンドの前段に Redis、その効果を数字で | 50分 |
| 8 · シークレット | パスワードをマニフェストから OpenBao へ移す | 50分 |
| 9 · 分析 | 100万行のレポートをミリ秒で | 45分 |
| 10 · ドキュメント | レコードごとに形が異なる MongoDB | 45分 |
| 11 · モバイルビルド | クラスターで APK をビルドし、bucket に格納する | 40分 |
| 12 · 隣に VM を | レガシーは移行のためにコンテナ化する必要はない | 30分 |
| 13 · 自分のものをカタログに | アプリケーションを Cozystack アプリとしてパッケージ化する | 40分 |
| 14 · オブザーバビリティ | グラフの中に自分自身の負荷の痕跡を見つける | 30分 |
| 15 · 月曜日に何をするか | どのシステムから始めるか、経営陣に何を約束するか | 20分 |

ラボへのリンクは、あなたの経路の README にあります：[`laptop/labs/`](laptop/labs/) または
[`bastion/labs/`](bastion/labs/)。
