## 16. ステップ2: 変換マシン

**変換を行う仮想マシンを立ち上げる**

📍 **場所:** bastion 上。

**「変換」とは何か、そしてなぜ避けて通れないのか。** 仮想マシンのディスクは1つのファイルです。VMware はそれを独自の形式 `VMDK` で保存します。Cozystack で仮想マシンを動かす KVM はこの形式を理解できず、`QCOW2` を必要とします。中身は同じ、あらゆる設定を含んだあなたの CentOS ですが、包み方が違うのです。変換とは、ファイルを一方の形式から他方の形式へ詰め替えることであり、データそのものは変わりません。

さらに、中身も手直しする必要があります。vSphere の中で育ったシステムは、VMware の仮想ハードウェアを見つけられると期待しています。専用のネットワークカード、専用のディスクコントローラー、`vmxnet3` と `pvscsi` のドライバーです。新しい住まいではハードウェアが違います。`virtio` です。適切なドライバーをあらかじめ起動イメージに仕込んでおかないと、マシンは起動してもディスクもネットワークも見つけられません。これも変換が面倒を見てくれます。

**なぜ仮想マシン自体ではなく、別のマシンなのか。** ツールの名前は `virt-v2v` で、これは大量の依存関係を引きずり、数十ギガバイトを食い潰します。全員が使う共有の bastion にこれを入れるのは悪手です。小さく、全員に1台しかないのですから。ストレージのすぐ隣にクラスター内で使い捨てのマシンを立て、その中で作業を済ませ、落とすほうが簡単です。

おまけに、これはまさに実際のマイグレーションプロジェクトで変換を行うときのやり方でもあります。コンバーターは VPN 越しの誰かの作業マシン上ではなく、データのすぐ隣に住むのです。

```bash
kubectl apply -f manifests/02-conversion-vm.yaml
kubectl get vminstance -n tenant-workshopXX -w
```

`Running` 状態になるのを待ちます(Ctrl+C で監視を終了します)。**コンソール経由**で中に入ります:

```bash
virtctl console --namespace=tenant-workshopXX vm-instance-convert
```

**変換マシンへのアクセス:**
```
login:    ubuntu
password: ubuntu
```

コンソールから抜けるには `Ctrl+]`。画面が真っ暗なら Enter を押します。

⚠️ **`virtctl ssh` では入らないでください。** 過去のワークショップでは誰一人としてうまくいきませんでした。`exit status 255` を返して接続を切ってしまいます。コンソールはクラスターの API を通るので常に動きます。同じことがマウスでもできます。ダッシュボードのマシンのページにある **VNC** ボタンです。

**このコマンドが正確に何を作ったのか。** ファイルには2つのオブジェクトが記述されているので、ダッシュボードには1つではなく2つのエントリが現れます:

• **VM Disk** `convert-tools` という名前の、カタログイメージ `ubuntu-20.04` からクローンされた 25Gi のディスク
• **VM Instance** `convert` という名前の、そのディスクを接続するマシン本体

仮想マシンはディスクなしには存在できません。だからディスクは常に最初に、別個のオブジェクトとして作られます。これを覚えておいてください。ステップ4でまったく同じ組み合わせが出てきます。

⚠️ そして名前について、混乱しないようにすぐ触れておきます。ダッシュボードでのオブジェクトは `convert` という名前ですが、それが立ち上げるマシンはクラスター内では **`vm-instance-convert`** という接頭辞付きの名前で知られています。ですからダッシュボードでは `convert` を探し、`virtctl` のコマンドでは `vm-instance-convert` と書きます。

🖱 **ダッシュボード経由:** 同じ2つのオブジェクトを、順番に手作業で作ります。
**1)** **VM Disk → Deploy new**: 名前 `convert-tools`、source = **image**、イメージ `ubuntu-20.04`、サイズ `25Gi`、storage class `replicated`。
**2)** **VM Instance → Deploy new**: 名前 `convert`、instance type `u1.large`、profile `ubuntu`、そしてディスクの一覧から `convert-tools` を選びます。一段階前に作ったあのディスクです。そのままそこの **VNC** ボタンで中に入れるので、ssh も virtctl も要らず、すべてブラウザで完結します。

⚠️ ディスクは 25Gi より小さくしないでください。イメージより小さいとクローンが通らず、そのうえディスクが Terminating 状態のまま固まって邪魔になります。

⚠️ マニフェストでは意図的に **ubuntu-20.04** イメージを指定しています。変更しないでください。24.04 ではマシンが起動せず、22.04 では CentOS 7 内部の古いパッケージデータベースで変換がつまずきます。あなたが確かめずに済むよう、私たちが確認済みです。
