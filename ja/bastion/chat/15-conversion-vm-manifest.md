## 15. 詳しく見る：02-conversion-vm.yaml の中身

このファイルには `---` の行で区切られた**2つ**のオブジェクトが入っています。YAML で複数の
ドキュメントを1つのファイルにまとめるときのやり方です。仮想マシンはディスクなしには存在
できないので、ディスクは別に記述され、常に最初に作成されます。

```yaml
kind: VMDisk
metadata:
  name: convert-tools
spec:
  source:
    image:
      name: ubuntu-20.04
  storage: 25Gi
  storageClass: replicated
```

`kind: VMDisk` — ディスクそれ自体であり、独立したオブジェクトです。これは慣れが必要です。
vSphere ではディスクはマシンの属性ですが、ここでは自立した存在で、あらかじめ作成しておき、
マシンに接続し、切り離して、別のマシンに接続できます。

`source.image.name: ubuntu-20.04` — 中身をどこから取ってくるか。これは先ほどの図にあった
あのイメージのカタログです。Cozystack は `cloud-images.ubuntu.com` から公式の Ubuntu 20.04
クラウドイメージをあらかじめダウンロードして手元に保持しています。ここではそこからコピーを
作るよう依頼しています。誰もそのためにインターネットへ取りに行きません。コピーはクラスター
の内部で作られます。

⚠️ **Ubuntu のバージョンは意図的に指定しているので、変更しないでください。** 24.04 では
マシンが起動しません。22.04 では再パッケージングが CentOS 7 内部の古い RPM パッケージ
データベースでつまずきます — `virt-v2v` がそれを解釈できないのです。あなたが試さずに済む
よう、検証済みです。

`storage: 25Gi` — ディスクのサイズ。カタログの Ubuntu イメージは 20Gi を占め、**ディスクは
イメージより大きくなければなりません**。さもないとコピーが途中で中断し、そのあとディスクが
`Terminating` の状態で固まって邪魔になります。余裕が必要なのは、ダウンロードした
`app-1.ova` と再パッケージングの結果がその中に同時に置かれるからでもあります。

`storageClass: replicated` — どう保存するか。`replicated` は異なるノード上に複数のコピーを
置くことを意味します。ノードが停止しても — データはそこにあります。相当するものは vSphere
のストレージポリシーです。ほかに `local` もあります — こちらは速いですが、単一のノード上に
しか存在しません。

```yaml
kind: VMInstance
metadata:
  name: convert
spec:
  instanceType: u1.large
  instanceProfile: ubuntu
  runStrategy: Always
  disks:
    - name: convert-tools
```

`instanceType: u1.large` — マシンのサイズで、「CPU がこれだけ、メモリがこれだけ」という
出来合いのセットです。ここでは CPU 2個とメモリ 8ギガバイトです。再パッケージングはイメージを
断片ごとにメモリに保持し、本気でそれを要求します。

`instanceProfile: ubuntu` — このゲストシステム向けに調整された仮想ハードウェア設定のセット
です。どのディスクコントローラーか、どのネットワークカードか、クロックをどう渡すか。もっとも
近いのは VM 作成ウィザードの「Guest OS Type」で、これも同じように選んだシステムに合わせて
十数個の設定を黙って変更します。

`runStrategy: Always` — マシンを起動したまま保ち、もし落ちたら復旧させます。これは「ホストの
起動時に自動起動する」ことではなく、常時有効なルールです。プラットフォームがマシンが起動して
いることを見張ります。

`disks` — どのディスクを接続するか。上で記述した `VMDisk` オブジェクトへの名前による参照です。

```yaml
  cloudInit: |
    #cloud-config
    password: ubuntu
    packages: [ libguestfs-tools, virt-v2v, qemu-utils ]
    runcmd:
      - [ bash, -c, "wget ... mc && chmod +x /usr/local/bin/mc" ]
```

`cloudInit` — マシンが初回起動時に自ら実行する指示です。これはあらゆるクラウドイメージの
標準的な仕組みです。システムは起動時にこのようなテキストを探し、実行します。vSphere で
もっとも近いのは Customization Specification で、ただしここではテキストで表現され、マシン
そのものと同じファイルに入っています。

ここでは、パスワードを設定し、`virt-v2v` をその依存関係とともにインストールし、`mc` を
ダウンロードするよう依頼しています。`mc` は S3 ストレージを扱うためのコンソールクライアントで、
結果を bucket にアップロードするのに使う、まさにそれです。

⚠️ **平文のパスワード** — 学習用のテスト環境だけのためです。マシンは30分だけ生きていて、
クラスターの内部からしかアクセスできません。実運用のマシンでは `password` の代わりに ssh 鍵を
配置します。
