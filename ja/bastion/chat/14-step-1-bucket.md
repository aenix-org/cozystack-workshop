## 14. ステップ1: 自分専用のストレージ

**イメージ用のバケットを作成する**

📍 **場所:** bastion 上、`~/workshop` ディレクトリで。

ディスクイメージは数ギガバイトあります。あとでクラスターがリンク経由でファイルを取得できるよう、どこかに置いておく必要があります。そのためのものがオブジェクトストレージで、S3 と同じ考え方です。

```bash
kubectl apply -f manifests/01-bucket.yaml
kubectl get buckets.apps.cozystack.io -n tenant-workshopXX
```

バケットが稼働状態になるまで待ってください。

このマニフェストは **`my-images`** という名前のバケットを、`app` という単一ユーザーとともに作成します。ダッシュボードでは **Bucket** セクションに表示されます。

🖱 **ダッシュボードから行う場合:** **Bucket → Deploy new**、名前は `my-images`。ただし必ず、作成する前に **ユーザー `app` をすぐに `users` セクションへ追加**してください。空のバケットを作ってからあとで Edit でユーザーを追記すると、バケットは中途半端な状態のままになり、イメージのアップロードが失敗します。マニフェストではこれがすでに考慮されています。

**では、バケットのキーを取得しましょう。2つ先のステップで必要になります。**

バケットはロックされており、そこに何かを入れるにはバケット専用のアクセスキーが必要です。キーはダッシュボードにあります: **Bucket → `my-images` → Secrets タブ → `bucket-my-images-app-credentials` という Secret**。これを展開すると4つの値が表示され、それぞれに *Reveal*(表示)ボタンと *Copy*(コピー)ボタンが付いています。

**今すぐやること: そのうち3つをメモ帳にコピーしてください。** どこでも構いません。メモアプリでも、自分宛ての下書きメッセージでも:

• `bucketName`
• `accessKey`
• `secretKey`

⚠️ **`bucketName` は `my-images` では**ありません**。** `my-images` はあなたが注文に付けた名前で、S3 上のバケットの本当の名前はプラットフォーム自身が生成した、`bucket-a9209f83-4ac1-463e-8477-d8365bef787b` のような長いものです。スクリプトに入れるのはまさにそれ、`bucketName` フィールドの値です。`my-images` を書き込むと、アップロードは存在しないバケットへ向かい、`Insufficient permissions` で失敗します。過去のワークショップでも、ここでつまずいた人がいました。

4つ目の `endpoint` は書き留める必要はありません。全員で共通の値で、すでにスクリプトに書き込まれています。

**これらの値をどこに入れるか。** ステップ3で、変換用マシン上のファイル `convert.sh` を開きます。その中に「PASTE YOUR VALUES」という3行のブロックがあります:

```
BUCKET="ВСТАВЬТЕ_bucketName"
ACCESS_KEY="ВСТАВЬТЕ_accessKey"
SECRET_KEY="ВСТАВЬТЕ_secretKey"
```

まさにこの3つの値を、それぞれの引用符の中に貼り付けます。これら以外の場所では必要ありません。スクリプトが自分で、できあがったイメージをあなたのバケットにアップロードし、自分でそれへのリンクを作成します。

⚠️ シークレットキーはあなたのストレージのパスワードです。共有チャットには投稿しないでください。助けを求めるときでもです。何かが合わないときは、私に個別にメッセージを送ってください。

⚠️ もし `endpoint` を自分のものに変更する場合: ダッシュボードではスキームなしで表示されます(`s3.workshop.aenix.io`)が、スクリプトには先頭に `https://` を **付けて** 書き込みます。付けないと、アップロードは何も言わずに失敗します。
