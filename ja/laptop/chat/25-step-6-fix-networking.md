## 25. ステップ6: マシン内部のネットワークを直す

**まずネットワーク、ほかは全部そのあとで**

📍 **場所:** あなたの仮想マシンの内部、コンソール上です。ノートパソコン上ではありません。

📄 これはリポジトリにある `scripts/netfix-dhcp.sh` の中身です。**マシンにダウンロードする必要はありませんし、そもそもできません** — マシンにはまだネットワークがなく、その欠けているネットワークこそが今回の故障だからです。コマンドは手で入力してください。2つだけです。あとで読み返せるように、ファイルはリポジトリに置いてあります。

アプリケーションは今ダウンしていますが、これはテスト環境の故障ではありません。イメージの中には過去が残っています。VMware ネットワークの静的アドレスと、ここには存在しないゲートウェイです。マシンはそれらにしがみつき、クラスターの DNS も隣人も見えていません。

コンソールからマシンに入ります — ノートパソコンから:
```bash
virtctl console --namespace=tenant-workshopXX vm-instance-app-1
```
🖱 **またはマウスで:** ダッシュボードで自分のマシンを開き、**VNC** をクリックします — 同じコンソールで、ブラウザ上にあるだけです。どちらの経路もクラスター API を通るので、マシン内部のネットワークが壊れている今でも動作します。

次は — マシンの内部で（これは CentOS なので、ネットワークは netplan ではなくここで設定します）:
```bash
sed -i 's/^BOOTPROTO=.*/BOOTPROTO=dhcp/; /^IPADDR/d; /^GATEWAY/d; /^NETMASK/d; /^PREFIX/d; /^DNS/d' /etc/sysconfig/network-scripts/ifcfg-eth0
```
何が出来上がったか、自分の目で確認してください:
```bash
cat /etc/sysconfig/network-scripts/ifcfg-eth0
```
`BOOTPROTO=dhcp` の行が残り、アドレスやゲートウェイの行は無くなっているはずです。`nano` で手作業で直しても結果は同じで、ただ時間がかかるだけです。

さて、マシンを再起動する必要があります:
```bash
reboot
```
🖱 **またはマウスで:** ダッシュボードのマシンのページにある **Restart** ボタンです。

再起動後、アドレスがクラスターのものになったか確認します:
```bash
ip -4 addr show eth0
```
`10.244.x.x` のような値になっているはずです。これはマシンがクラスターネットワーク上にあり、その DNS が見えていることを意味します。

⚠️ 順番が重要です: アドレスがまだ古いままのうちは、サービス名が解決されず、アプリケーションの設定を編集しても意味がありません。
