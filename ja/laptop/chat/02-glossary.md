## 2. ちょっとした用語集: あなたのところでの呼び方と、ここでの呼び方

**あとで何度でも戻ってこられる、ひとつのメッセージ**

ワークショップでの混乱の半分は、技術そのものではなく言葉についてのものです。以下がその対訳です。アナロジーが誤解を招くところでは、正直にどこがそうなのかを書きます。間違ったアナロジーは、アナロジーがないよりも悪いからです。

| vSphere では | Cozystack / Kubernetes では | アナロジーが誤解を招くところ |
|---|---|---|
| 仮想マシン | **VM Instance** | ここには誤解を招くところはありません。まさにそのとおりのものです |
| VM のディスク | **VM Disk** | 別個のオブジェクトです。ディスクなしの VM は存在しないので、ディスクが常に最初に作成されます |
| VM テンプレート | カタログ内のイメージ | — |
| アプリケーションのコンテナ | **Pod** | Pod は使い捨てです。修理はせず、削除すると新しいものが作られます |
| vApp | **Deployment** | — |
| リソースプール | クォータ付きの **テナント** | テナントはアクセス境界でもあります。部外者は中を覗けません |
| vCenter | API サーバー | ダッシュボードはその顔であって、それ自体ではありません |
| HA | **Deployment** が N 個のコピーを保つ | 「落ちたものを起こし直す」のではなく、「指定した数だけ常に保つ」のです |
| ロードバランサーのプール | **Service** | — |
| データストア | **Storage Class** | `replicated` — 3 つのノードにレプリケーション、`local` — レプリケーションなし |
| Postgres 用の専用 VM | **カタログの Postgres** | レプリケーションとバックアップ付きで届き、自分で更新します |
| IT 部門への申請 | *アナロジーなし* | 自分で、1 分でやります |

**慣れる必要があることがひとつ。** vSphere ではオブジェクトを**作成**します。クリックすれば現れ、そのあとは自分で存在し続けます。ここでは**望ましい状態を記述**し、クラスターがそれを実際の状態と絶えず比較して差分を解消します。ですから、何かを削除しても戻ってくることがあります。不具合だからではなく、望みを取り消していないからです。
