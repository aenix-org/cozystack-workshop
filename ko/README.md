# VMware에서 Cozystack로 마이그레이션하기: 워크숍과 랩

VMware를 관리하면서 Cozystack가 무엇인지 이해하고 싶은 분들을 위한 자료입니다 —
슬라이드가 아니라 직접 손으로 해보면서 말이죠. Kubernetes를 몰라도 됩니다. 모든 것은
여러분이 이미 vSphere에서 알고 있는 것을 통해 진행하면서 설명됩니다.

## 수강 방법 두 가지 — 자신에게 맞는 것을 고르세요

같은 워크숍이 두 가지 형태로 제공됩니다. 둘의 차이는 오직 **클러스터를 어디에서
다루는가** 하나뿐입니다. 어느 쪽이 여러분 것인지는 강사가 알려줍니다.

| | [`laptop/`](laptop/) — 자신의 노트북에서 | [`bastion/`](bastion/) — bastion(공유 VM)을 통해 |
|---|---|---|
| **도구** | 직접 설치합니다: `kubectl`, `virtctl`, `kubelogin` | bastion에 이미 설치되어 있음 |
| **클러스터 접근** | 대시보드에서 받은 kubeconfig로 브라우저를 통해 로그인 | SSH로 로그인, 접근 권한은 이미 설정되어 있음 |
| **파일 안의 테넌트 번호** | 직접 채워 넣습니다 | 미리 채워져 있음 |
| **앱 확인** | `virtctl port-forward` + `localhost:8080` | 도메인 이름 `app.<number>.workshop.aenix.io` 으로 |
| **대상** | 공유 bastion이 없는 사람 | bastion이 갖춰진 준비된 테스트베드 |

각 폴더 안에는 자체적으로 완결된 세트가 들어 있습니다: 자체 `README.md`(경로), `chat/`
(각 단계별 채팅 메시지), `manifests/`, `scripts/`. 자신의 경로에 해당하는 README를 열어
따라가세요.

## 랩

두 폴더 모두 `labs/`를 포함합니다 — 집에서든 쉬는 시간에든 자신의 속도로 진행하는 열여섯
개의 독립적인 랩입니다. 각 랩에는 자체 확인 스크립트(`check/`)가 딸려 있습니다. 전체 세트는
약 아홉 시간 분량으로, 한 번에 끝내라고 만든 것이 아닙니다: 저녁마다 하나씩 하세요.

| 랩 | 내용 | 시간 |
|---|---|---|
| 0 · 나만의 클러스터 | 10분 만에 Kubernetes 하나 마련하기 | 15분 |
| 1 · 첫 애플리케이션 | 파일 하나와 명령 하나로 애플리케이션 배포하기 | 25분 |
| 2 · 자가 복구 | 레플리카를 삭제하고 무슨 일이 벌어지는지 보기 | 25분 |
| 3 · 스케일링 | 부하를 주고 레플리카가 늘어나는 것을 지켜보기 | 30분 |
| 4 · 롤아웃과 롤백 | 부하가 걸린 상태에서 다운타임 없이 버전 바꾸기 | 30분 |
| 5 · Git 안의 인프라 | 모든 것을 저장소에 기술하고 push 한 번으로 배포하기 | 40분 |
| 6 · 나만의 레지스트리 | Harbor, Go 서비스 빌드, 나만의 레지스트리에서 배포하기 | 45분 |
| 7 · 캐시 | 느린 백엔드 앞에 Redis, 그 이득을 수치로 | 50분 |
| 8 · 시크릿 | 비밀번호를 매니페스트에서 OpenBao로 옮기기 | 50분 |
| 9 · 분석 | 백만 행과 밀리초 단위의 리포트 | 45분 |
| 10 · 문서 | 레코드마다 구조가 다른 MongoDB | 45분 |
| 11 · 모바일 빌드 | 클러스터에서 APK를 빌드해 버킷에 넣기 | 40분 |
| 12 · 나란히 두는 VM | 옮겨오기 위해 레거시를 컨테이너화할 필요는 없습니다 | 30분 |
| 13 · 카탈로그에 나만의 앱 | 애플리케이션을 Cozystack 앱으로 패키징하기 | 40분 |
| 14 · 옵저버빌리티 | 그래프에서 자신이 만든 부하의 흔적 찾기 | 30분 |
| 15 · 월요일에 무엇을 할까 | 어떤 시스템부터 시작하고 경영진에게 무엇을 약속할까 | 20분 |

각 랩으로 가는 링크는 자신의 경로에 해당하는 README에 있습니다: [`laptop/labs/`](laptop/labs/) 또는
[`bastion/labs/`](bastion/labs/).
