## 17. 자세히 살펴보기: convert.sh 안에는 무엇이 있나

이 스크립트는 다섯 단계로 이루어져 있으며, 각 단계는 지금 무엇을 하고 있는지 출력합니다.

**1단계 — 하드웨어 가속 확인.** `/dev/kvm` 장치가 있는지 확인합니다.
`virt-v2v`는 이미지 내부로 들어가기 위해 내부적으로 작은 가상 머신을 하나 띄웁니다.
프로세서가 우리 머신 안으로 패스스루되면 이 중첩 가상화는 빠르게 진행됩니다.
그렇지 않으면 소프트웨어 모드가 켜집니다. 느리지만 동작은 합니다.
`LIBGUESTFS_BACKEND=direct` 라인이 바로 그런 모드로 전환하는 스위치입니다.

**2단계 — 원본 이미지 다운로드.**

```bash
wget -O source.ova "$OVA_URL"
```

워크숍 공유 스토리지에서 `app-1.ova`를 가져옵니다. 위 지도에 나온 바로 그 스토리지입니다.
강사가 미리 그곳에 파일을 올려 두었습니다. **여러분의 실제 프로젝트라면 이 자리에
vSphere에서의 내보내기가 들어갑니다:** `Export OVF Template` 또는 `ovftool`, 그리고
이어지는 동일한 재패키징입니다.

**3단계 — 재패키징 그 자체.**

```bash
virt-v2v -i ova /root/source.ova -o local -os /root/out -of qcow2 -on app
```

`-i ova` — 입력이 무엇인지: OVA 형식의 파일. `-o local -os /root/out` — 결과를 어디에
둘지: 로컬 폴더 `/root/out`. `-of qcow2` — **필수** 플래그입니다: 이것이 없으면
`virt-v2v`가 기본 형식을 고르고, 플랫폼은 그런 디스크를 받아 주지 않습니다. `-on app` —
결과에 붙일 이름이며, 여기서 파일 이름 `app.qcow2`가 나옵니다.

이 작업은 몇 분 걸립니다. 화면에는 `Copying disk 1/1` 같은 줄이 지나갑니다. 앞서 말한,
드라이버와 관련된 그 두 번째 보이지 않는 작업이 바로 여기서 일어납니다.

**4단계 — 여러분의 bucket으로 업로드.**

```bash
mc alias set mybucket "$S3_ENDPOINT" "$ACCESS_KEY" "$SECRET_KEY"
mc cp /root/out/app.qcow2 "mybucket/$BUCKET/app.qcow2"
```

`mc alias set`은 스토리지 주소와 키를 `mybucket`이라는 짧은 이름으로 기억해 두어,
이후 모든 명령에서 그것들을 반복하지 않아도 되게 합니다. `mc cp`는 파일을 복사합니다.
문법은 일부러 일반적인 `cp`와 똑같게 되어 있습니다.

**5단계 — 플랫폼을 위한 링크.**

```bash
mc share download --expire 168h "mybucket/$BUCKET/app.qcow2"
```

7일(168시간) 동안 유효한 임시 서명된 링크를 만듭니다. 서명되었다는 것은 주소 안에
암호학적 서명이 새겨져 있다는 뜻으로, 이 링크만 있으면 누구나 파일을 다운로드할 수
있지만, 오직 이 링크로만 그리고 링크가 살아 있는 동안에만 가능합니다. bucket을 온
세상에 열어 둘 필요도 없고, 접근 키를 플랫폼에 넘겨줄 필요도 없습니다.

링크는 출력에서 `Share:` 라는 단어 뒤에서 찾으세요. 다음 단계에서 필요합니다.
