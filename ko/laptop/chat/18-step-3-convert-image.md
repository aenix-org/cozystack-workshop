## 18. 3단계: 이미지 변환

**VMware 이미지를 KVM 이미지로 바꾸기**

📍 **위치:** 방금 콘솔로 접속한 변환기 머신 내부입니다. 노트북이 아닙니다.

📄 `scripts/convert.sh`로 작업합니다. 이 머신은 네트워크에 접근할 수 있으므로 파일을 스스로
내려받습니다. 클립보드로 복사할 필요가 없습니다.

GitHub에서 스크립트를 머신으로 바로 가져옵니다:
```bash
curl -fsSLO https://raw.githubusercontent.com/aenix-org/cozystack-migration-workshop/master/laptop/scripts/convert.sh
```

엽니다:
```bash
nano convert.sh
```

**1단계에서 메모해 둔 세 개의 값이 바로 여기서 쓸모가 있습니다.** 파일 상단에
«값을 붙여넣으세요»라고 표시된 블록이 있습니다. 따옴표는 그대로 두고 그 안의
플레이스홀더를 여러분의 값으로 바꾸세요:

```
BUCKET="your-bucket-name"
ACCESS_KEY="your-accessKey"
SECRET_KEY="your-secretKey"
```

`S3_ENDPOINT` 줄과 원본 이미지 링크는 건드리지 마세요. 이미 올바르게 되어 있고 모두에게
동일합니다.

nano에서 저장하기: `Ctrl+O`, 그다음 `Enter`, 그다음 종료하려면 `Ctrl+X`. 플레이스홀더가
남아 있지 않은지 확인하세요:
```bash
grep ВСТАВЬТЕ convert.sh || echo "all filled in, ready to run"
```

실행합니다. 반드시 `sudo`로 실행하세요. 스크립트에는 root 권한이 필요합니다:
```bash
sudo bash convert.sh
```

내부에서 벌어지는 일: 스크립트는 원본 이미지를 내려받고, `virt-v2v`를 실행하고, 결과를
압축한 뒤 여러분의 bucket에 업로드합니다.

가장 중요한 작업은 `virt-v2v`가 합니다. 이것은 파일 형식만 바꾸는 게 아닙니다: 게스트
시스템 안으로 virtio 드라이버를 밀어 넣고 부트로더를 고쳐 줍니다. 이것이 없으면 머신은
새 하이퍼바이저에서 아예 시작조차 되지 않습니다.

⏳ **이 작업은 약 5분이 걸립니다.** 우리 테스트베드에는 중첩 가상화가 없어서 변환은 에뮬레이션
모드로 진행됩니다. 진행 상황은 콘솔에 보입니다. 콘솔을 닫지 마세요.

끝에서 스크립트는 여러분의 이미지에 대한 **presigned 링크**를 출력합니다. 출력에서 `Share:`라는
단어로 시작하는 줄을 찾으세요. 링크는 바로 그 뒤에 옵니다.

**이 링크로 할 일:** 같은 메모장에 복사하세요. 다음 단계에서 노트북으로 돌아가
`manifests/03-app-vm.yaml`을 열고, 지금 `ВСТАВЬТЕ_PRESIGNED_URL` 플레이스홀더가 있는
`url` 필드에 붙여 넣습니다. 우리가 번호를 채워 넣을 때 제가 미리 경고했던 바로 그 필드입니다.

이것은 임시 서명 링크입니다: 저장소는 외부로 열려 있지 않고, 링크는 여러분 자신의 키로 만든
것입니다. 이 링크는 일주일 동안 유효합니다. 워크숍과 그 뒤의 실험에 쓰기에 넉넉합니다.
