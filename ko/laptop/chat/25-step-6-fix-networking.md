## 25. 6단계: 머신 내부의 네트워크를 고친다

**먼저 네트워크, 그다음에 나머지 전부**

📍 **위치:** 여러분의 가상 머신 내부, 콘솔 안. 노트북이 아닙니다.

📄 이것은 저장소에 있는 `scripts/netfix-dhcp.sh`의 내용입니다. **머신 안으로 내려받을 필요도 없고, 내려받을 수도 없습니다** — 머신에는 아직 네트워크가 없고, 바로 그 없는 네트워크가 우리의 고장입니다. 명령은 직접 손으로 입력합니다. 두 개뿐입니다. 파일이 저장소에 있는 것은 나중에 다시 읽어보기 위함입니다.

애플리케이션은 지금 멈춰 있고, 이것은 테스트베드의 고장이 아닙니다. 이미지 안에는 과거가 아직 남아 있습니다. VMware 네트워크에서 온 정적 주소와, 여기에는 존재하지 않는 게이트웨이입니다. 머신은 그것들을 붙들고 있어서 클러스터 DNS도, 이웃도 보지 못합니다.

콘솔을 통해 머신 안으로 들어갑니다 — 노트북에서:
```bash
virtctl console --namespace=tenant-workshopXX vm-instance-app-1
```
🖱 **또는 마우스로:** 대시보드에서 여러분의 머신을 열고 **VNC**를 클릭하세요 — 같은 콘솔이고, 다만 브라우저 안일 뿐입니다. 두 경로 모두 클러스터 API를 거치며, 머신 내부의 네트워크가 망가진 지금도 작동합니다.

다음은 — 머신 내부에서 (이것은 CentOS이고, 네트워크는 netplan이 아니라 여기서 설정합니다):
```bash
sed -i 's/^BOOTPROTO=.*/BOOTPROTO=dhcp/; /^IPADDR/d; /^GATEWAY/d; /^NETMASK/d; /^PREFIX/d; /^DNS/d' /etc/sysconfig/network-scripts/ifcfg-eth0
```
무엇이 나왔는지 직접 눈으로 확인하세요:
```bash
cat /etc/sysconfig/network-scripts/ifcfg-eth0
```
`BOOTPROTO=dhcp` 줄은 남아 있어야 하고, 주소나 게이트웨이가 있는 줄은 없어야 합니다. `nano`로 직접 손으로 고쳐도 결과는 같습니다. 다만 더 느릴 뿐입니다.

이제 머신을 재시작해야 합니다:
```bash
reboot
```
🖱 **또는 마우스로:** 대시보드의 머신 페이지에 있는 **Restart** 버튼.

재부팅 후에는 주소가 클러스터 주소로 바뀌었는지 확인하세요:
```bash
ip -4 addr show eth0
```
`10.244.x.x` 같은 형태여야 합니다. 그것은 머신이 클러스터 네트워크에 있고 그 DNS를 본다는 뜻입니다.

⚠️ 순서가 중요합니다: 주소가 아직 예전 것인 동안에는 서비스 이름이 해석되지 않고, 애플리케이션의 설정을 고치는 것도 의미가 없습니다.
