## 25. स्टेप 6: मशीन के अंदर नेटवर्क ठीक करें

**पहले नेटवर्क, बाकी सब उसके बाद**

📍 **कहाँ:** आपकी वर्चुअल मशीन के अंदर, कंसोल में। लैपटॉप पर नहीं।

📄 यह रिपॉज़िटरी से `scripts/netfix-dhcp.sh` की सामग्री है। **आपको इसे मशीन में डाउनलोड करने की ज़रूरत नहीं है, और आप कर भी नहीं सकते** — मशीन के पास अभी कोई नेटवर्क नहीं है, और यही ग़ायब नेटवर्क ठीक हमारी ख़राबी है। कमांड हाथ से टाइप करें; वे दो हैं। फ़ाइल रिपॉज़िटरी में रहती है ताकि आप बाद में इसे दोबारा पढ़ सकें।

एप्लिकेशन अभी बंद है, और यह परीक्षण मंच की ग़लती नहीं है। बीता हुआ अतीत अब भी इमेज के अंदर बना हुआ है: VMware नेटवर्क से एक स्टैटिक पता और एक गेटवे जो यहाँ मौजूद ही नहीं। मशीन उन्हीं से चिपकी रहती है और न क्लस्टर DNS देख पाती है, न अपने पड़ोसियों को।

कंसोल के ज़रिए मशीन में प्रवेश करें — लैपटॉप से:
```bash
virtctl console --namespace=tenant-workshopXX vm-instance-app-1
```
🖱 **या माउस से:** डैशबोर्ड में, अपनी मशीन खोलें और **VNC** पर क्लिक करें — यह वही कंसोल है, बस ब्राउज़र में। दोनों रास्ते क्लस्टर API से होकर जाते हैं और अभी भी काम करते हैं, जबकि मशीन के अंदर नेटवर्क टूटा हुआ है।

आगे — मशीन के अंदर (यह CentOS है, नेटवर्क यहाँ कॉन्फ़िगर होता है, netplan में नहीं):
```bash
sed -i 's/^BOOTPROTO=.*/BOOTPROTO=dhcp/; /^IPADDR/d; /^GATEWAY/d; /^NETMASK/d; /^PREFIX/d; /^DNS/d' /etc/sysconfig/network-scripts/ifcfg-eth0
```
अपनी आँखों से देखें कि क्या निकला:
```bash
cat /etc/sysconfig/network-scripts/ifcfg-eth0
```
`BOOTPROTO=dhcp` वाली लाइन बनी रहनी चाहिए, और पते या गेटवे वाली कोई लाइन नहीं होनी चाहिए। अगर आप इसे `nano` से हाथ से संपादित करें, तो नतीजा वही होगा, बस धीमा।

अब मशीन को रीस्टार्ट करना होगा:
```bash
reboot
```
🖱 **या माउस से:** डैशबोर्ड में, मशीन के पेज पर, **Restart** बटन।

रीबूट के बाद, जाँचें कि पता क्लस्टर वाला बन गया है:
```bash
ip -4 addr show eth0
```
यह कुछ ऐसा होना चाहिए जैसे `10.244.x.x`। इसका मतलब है कि मशीन क्लस्टर नेटवर्क पर है और अपना DNS देख रही है।

⚠️ क्रम मायने रखता है: जब तक पता पुराना ही है, सेवा नाम रिज़ॉल्व नहीं होते, और एप्लिकेशन का कॉन्फ़िग संपादित करने का कोई मतलब नहीं।
