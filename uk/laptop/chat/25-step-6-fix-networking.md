## 25. Крок 6: лагодимо мережу всередині машини

**Спочатку мережа, потім усе інше**

📍 **Де:** всередині вашої віртуальної машини, у консолі. Не на ноутбуці.

📄 Це вміст `scripts/netfix-dhcp.sh` з репозиторію. **Завантажувати його в машину не треба, та й не вийде** — мережі в неї поки що немає, і саме ця відсутня мережа і є нашою поломкою. Команди набираємо руками, їх дві. Файл лежить у репозиторії — щоб перечитати потім.

Застосунок зараз не працює, і це не поломка тестового середовища. Всередині образу залишилося минуле: статична адреса з мережі VMware і шлюз, якого тут немає. Машина тримається за них і не бачить ні кластерного DNS, ні сусідів.

Зайдіть у машину через консоль — з ноутбука:
```bash
virtctl console --namespace=tenant-workshopXX vm-instance-app-1
```
🖱 **Або мишкою:** у дашборді відкрийте свою машину і натисніть **VNC** — це та сама консоль, тільки в браузері. Обидва шляхи йдуть через API кластера і працюють навіть зараз, коли мережа всередині машини зламана.

Далі — всередині машини (це CentOS, мережа налаштовується тут, а не в netplan):
```bash
sed -i 's/^BOOTPROTO=.*/BOOTPROTO=dhcp/; /^IPADDR/d; /^GATEWAY/d; /^NETMASK/d; /^PREFIX/d; /^DNS/d' /etc/sysconfig/network-scripts/ifcfg-eth0
```
Перевірте очима, що вийшло:
```bash
cat /etc/sysconfig/network-scripts/ifcfg-eth0
```
Має залишитися рядок `BOOTPROTO=dhcp`, а рядків з адресою і шлюзом бути не повинно. Якщо правите вручну через `nano` — результат той самий, лише повільніше.

Тепер машину треба перезапустити:
```bash
reboot
```
🖱 **Або мишкою:** у дашборді на сторінці машини кнопка **Restart**.

Після перезавантаження перевірте, що адреса стала кластерною:
```bash
ip -4 addr show eth0
```
Має бути щось на кшталт `10.244.x.x`. Отже, машина в мережі кластера і бачить його DNS.

⚠️ Порядок важливий: поки адреса стара, імена сервісів не розв'язуються, і правити конфіг застосунку немає сенсу.
